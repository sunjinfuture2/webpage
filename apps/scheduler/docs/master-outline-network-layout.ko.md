# 통합 마스터 일정과 업무 관계도 — 0.6.0

## 목표와 화면 구조

전체 개요와 간트를 오가던 흐름을 하나의 마스터 일정으로 합친다. 사용자는 먼저 단계별 기간을 보고, 필요한 단계만 펼쳐 같은 시간축에서 세부 업무를 확인한다. 관계도는 업무 사이의 흐름을 읽고 관계를 수정하는 화면으로 사용한다. 두 화면은 동일한 Plan과 계산 결과를 사용한다.

제공된 디자인의 흰 바탕, 얇은 구분선, 파스텔 단계 칩과 절제된 주황 강조를 유지한다. PDF의 수동 묶음이나 업무명에서 선후행 관계를 추측하지 않는다. 원본 문서의 내용은 참고 데이터로만 다룬다.

## 한 화면에서 개요와 상세 보기

1. 첫 방문은 모든 단계가 접힌 상태로 시작한다. 단계 행에 기간, 업무 수, 완료 수, 최소 운영 여유와 주요 일정 지점을 표시한다.
2. 단계 이름 왼쪽 화살표 또는 요약 막대를 누르면 그 단계 아래에 세부 업무가 펼쳐진다. 다시 누르면 접힌다. 다른 단계의 펼침 상태는 유지한다.
3. 단계 요약과 업무 막대는 같은 날짜 좌표를 사용한다. 요약 막대는 하위 업무의 첫 시작부터 마지막 완료까지의 범위이며, 그 기간 내내 작업이 연속된다는 뜻은 아니다. 조건부 미발동 업무도 표시 기간에 포함하며 개수를 별도로 안내한다. 최소 여유 계산에서는 완료·조건부 미발동 업무를 제외한다.
4. 주요 일정 다이아몬드를 누르면 해당 단계를 펼치고 업무 상세를 연다. 주요 승인 지점은 원본 게이트의 업무 연결에서 가져온다.
5. 모두 펼치기·모두 접기와 전체 기간 맞춤을 제공한다. 상세 편집은 일·주 단위 축척에서 수행할 수 있다. 검색·필터·연결 집중 보기에서는 일치하는 업무를 자동으로 펼치고 그 상태를 안내한다.
6. 연결 집중 보기를 닫으면 진입 전 검색·필터·날짜·축척을 복원한다. 펼침 상태는 작업공간 설정에 저장한다.
7. 이전 `view=overview` 링크와 백업은 통합 일정으로 연결한다. 기존 작업공간을 처음 여는 때에만 새 개요 기본값으로 전환하며 일정 데이터와 시나리오는 보존한다.

단계 행은 64px, 업무 행은 38px이다. 누적 높이 배열과 이진 탐색으로 화면에 필요한 행을 구한다. 연결선 끝점도 같은 누적 높이를 사용하므로 여러 단계를 일부만 펼쳐도 선과 행이 어긋나지 않는다. 좁은 화면은 같은 단계 트리를 표로 제공한다.

## 관계도 연결선이 얽히던 원인

- 모든 관계가 비슷한 중앙 꺾임 위치를 사용해 세로선이 겹쳤다.
- 여러 열을 건너뛰는 연결이 중간 업무 카드가 있는 영역을 통과했다.
- 많은 카드와 약어를 한 번에 표시하면 개별 업무의 선행·후행을 따라가기 어려웠다.
- 카드를 누르는 즉시 중심 업무와 배치가 바뀌어 사용자가 읽던 위치를 잃었다.

## 배치와 경로 계산 순서

| 단계 | 적용 규칙 | 목적 |
| --- | --- | --- |
| 표시 범위 | 기본은 중심 업무의 직접 선행·후행. 필요할 때 2~4단계 또는 전체 연결로 확장 | 첫 화면의 밀도 조절 |
| 가까운 업무 선택 | 전체 범위가 표시 한도를 넘으면 중심 업무에서 연결을 따라 잰 거리순으로 선택 | 중심 업무 주변의 연결 맥락 유지 |
| 좌우 열 배정 | 활성 관계의 위상 순서로 선행은 왼쪽, 후행은 오른쪽에 배치 | 흐름 방향을 일관되게 표시 |
| 긴 연결 처리 | 여러 열을 건너뛰는 선은 중간 열마다 보이지 않는 통과 자리를 예약 | 업무 카드 관통 방지 |
| 교차 감소 | 인접 열의 연결 위치 평균으로 행 순서를 번갈아 8회 조정하고 교차 지표가 가장 낮은 결과를 채택 | 교차를 늘리지 않으며 불필요한 엇갈림 감소 |
| 연결점 분리 | 같은 카드에서 나가는 선과 들어오는 선에 서로 다른 높이의 연결점 배정 | 병렬 관계가 한 선처럼 보이는 현상 감소 |
| 통로 배정 | 세로 구간이 겹치는 선에는 서로 다른 통로 배정. 필요한 통로 수에 따라 열 간격 확장 | 긴 세로선 중첩 감소 |
| 예외 경로 | 역방향·같은 열의 조건부 관계는 카드 위쪽 외곽으로 우회 | 비활성 분기가 활성 업무의 순서를 바꾸지 않도록 처리 |
| 선 표현 | 직각 경로에 작은 둥근 모서리, 선 아래 흰 테두리, 명확한 화살표 | 교차 지점과 선의 방향 구별 |

교차 감소는 휴리스틱이다. 모든 그래프에서 교차를 완전히 없애거나 최적 배치를 보장하지 않는다. 내부 지표는 인접 열의 순서 교차 수이며 모든 픽셀 교차 수와 같지 않다. 일부 교차가 남더라도 카드 관통을 막고 선택 강조로 읽을 수 있도록 한다.

관계도 카드의 연결점은 **선행 → 후행** 흐름을 뜻한다. FS·SS·FF·SF의 시작·완료 의미는 관계 유형 표시와 상세 설명으로 확인한다. 날짜 축이 있는 간트에서는 기존처럼 실제 시작·완료 끝점에 연결한다. 화면 배치 때문에 관계 유형이나 간격을 변환하지 않는다.

## 선택과 수정

- **카드 선택:** 위치를 유지하고 그 업무와 직접 연결된 선·업무를 강조한다. 나머지 선은 옅게 표시한다. 카드 선택만으로 중심 업무나 일정은 바뀌지 않는다.
- **이 업무 중심으로:** 명시적인 동작으로 탐색 중심과 표시 범위를 바꾼다.
- **선 선택:** 선택 선을 위에 그리고 유형·간격·선행·후행·조건을 표시한다. 복잡한 화면에서는 선택·호버한 선 위주로 약어를 보여준다.
- **관계 추가·수정·삭제:** 기존 관계 편집기를 재사용한다. 자기 연결·중복·순환을 검증한 후 공통 명령으로 적용한다. 같은 Plan을 다시 계산하므로 간트·캘린더·관계도·운영개시 예상이 함께 갱신된다. 실행취소와 자동 저장을 사용한다.
- **일정에서 보기:** 해당 업무와 직접 연결된 업무를 통합 마스터 일정에 펼쳐 보여준다.

관계선과 카드의 접근 가능한 이름, 키보드 선택, 목록 보기를 유지한다. 반복 점멸이나 흐르는 선 효과는 넣지 않는다. 색·테두리 변화와 짧은 패널 전환을 사용하며 `prefers-reduced-motion`에서는 부드러운 스크롤과 애니메이션을 끈다.

## 계산과 표시의 경계

관계도는 최대 120개 업무·600개 관계를 표시하며 생략 수를 안내한다. 긴 연결의 통과 자리는 최대 3,500개이고 초과 연결은 외곽으로 우회한다. 표시 제한은 원본 업무·관계 삭제, 활성 상태 변경 또는 계산 입력 축소를 의미하지 않는다. 전체 관계는 관계 목록과 일정 계산에 유지한다.

‘전체 연결’에서 가까운 업무를 고르는 거리는 방향을 무시한 연결 거리다. 이를 지연 전파 경로라고 표시하지 않는다. 선행·후행 탐색은 각 방향을 독립적으로 따라가므로 선행 업무의 다른 후행을 선택 업무의 영향으로 혼동하지 않는다.

원본 참조계획, 실제일, 미입력값, 조건부 상태, 달력일 계산, 연결 프로젝트 사본과 시나리오 경계를 보존한다. 이 변경은 자원 평준화·근무 달력·공동 편집 기능을 추가하는 작업이 아니다.

## 구현 위치와 검증

- `Gantt.tsx`, `gantt-outline.ts`: 통합 단계 트리, 누적 높이, 가상화와 연결점 좌표.
- `network.ts`: 표시 범위, 가까운 업무 선택, 활성 관계의 열 배정.
- `network-routing.ts`: 가상 통과 자리, 교차 감소, 연결점과 통로 배정, 장애물 회피 경로.
- `NetworkView.tsx`: 배치를 유지하는 선택 강조, 관계 편집기와 일정 이동 연결.
- `App.tsx`, `seed.ts`, `storage.ts`: 공통 관계 명령, 보기 설정과 기존 링크·백업 호환.

공개 합성 테스트는 가변 높이 행 경계, 회피 가능한 교차 감소, 긴 연결·역방향 조건부 연결의 카드 관통 여부, 네 관계 유형의 병렬 연결, 분기·합류, 결정적 배치와 표시 한도를 검증한다. 실제 원본 파일의 화면·드래그·편집·백업 호환·새로고침·모바일 검증 자료는 비공개 작업 경로에만 저장한다.

## 후속 개발 프롬프트

> SUNJIN Schedule의 마스터 일정은 단일 단계 트리와 날짜 축으로 유지하라. 전체 개요와 상세 간트를 별도 화면으로 나누지 말고 각 단계 아래에 업무를 독립적으로 펼쳐라. 가변 행 높이의 가상화·연결점·선택 스크롤은 같은 좌표 계산을 사용하라. 관계도는 범위 선택 → 활성 관계의 열 배정 → 긴 연결의 빈 통과 자리 확보 → 교차 감소 → 연결점 분리 → 겹치는 세로 구간의 통로 분리 순서로 배치하라. 카드 선택은 배치를 바꾸지 말고 연결을 강조하며, 중심 변경은 별도 명시적 조작으로 제공하라. 관계도는 선행·후행 흐름, 간트는 실제 시작·완료 끝점을 표현하고 FS/SS/FF/SF와 간격은 그대로 보존하라. 편집은 기존 검증·명령·재계산·저장·실행취소 경로에 연결하라. 표시 제한은 계산 입력을 줄이지 않아야 한다. 교차가 완전히 제거된다고 표현하지 말라. 기존 링크·백업, 실제일·참조계획·조건부 상태와 시나리오 경계를 유지하라. 키보드·터치·좁은 화면·동작 줄이기를 검증하고 원본 문서·일정 데이터·실제 업무 스크린샷은 공개 저장소에 포함하지 말라.
