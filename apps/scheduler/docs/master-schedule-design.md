# 프로젝트 마스터 일정 디자인 기준

검토일: 2026-11-09. 사용자가 제공한 캘린더 이미지를 화면 구성의 기준으로 삼고, 기존 WorkSpace의 디자인 토큰과 대조했다. 이 문서는 화면 표현에 관한 기준이다. 일정 계산과 원본 데이터는 별도로 유지한다.

## 이미지에서 확인한 시각 규칙

화면은 흰 바탕 위의 제목·필터·일정으로 구성된다. 검정 월 제목이 시선을 잡고, 프로젝트를 나타내는 작은 파스텔 칩과 낮은 일정 막대가 내용을 구분한다. 주 구분선은 옅고, 세로 격자나 두꺼운 카드 테두리는 거의 드러나지 않는다. 일정이 적은 주의 빈 공간도 화면의 일부로 남긴다.

| 요소 | 관찰한 비례와 표현 | 앱 적용 기준 |
| --- | --- | --- |
| 바탕 | 순백색, 그림자와 장식 최소화 | 마스터 일정의 본문을 하나의 흰 작업면으로 구성한다. |
| 제목 | 검정, 약 29px, 중간 이상 굵기 | 월 제목의 계층을 분명히 하고 보조 문구의 대비를 낮춘다. |
| 외곽 여백 | 첨부 폭 기준 좌우 약 5~6% | 데스크톱은 여유 있게, 모바일은 축소한다. 고정 폭은 복제하지 않는다. |
| 월 이동 | 작고 옅은 좌우 화살표 | 제목 가까이 배치하고 키보드·터치로 사용할 수 있게 한다. |
| 프로젝트 칩 | 약 20px 높이, 둥근 끝, 작은 글자 | 실제 등록 프로젝트에만 색을 부여하고 선택 상태를 표시한다. |
| 유형 범례 | 오른쪽의 작은 기호와 짧은 이름 | 실제 업무 유형만 표시하고 작은 화면에서는 줄을 나눈다. |
| 요일·날짜 | 약 10~11px, 날짜는 검정 중심 | 일요일·토요일·다른 달 날짜를 구분한다. |
| 주 구분 | 약 100px 이상 높이, 얇은 수평선 | 기본 호흡을 유지하며 일정 겹침과 표시 개수에 대응한다. |
| 오늘 | 해당 날짜 영역의 아주 옅은 회색 | 프로젝트 상태일과 의미를 구분한다. |
| 일정 막대 | 약 17~20px 높이, 작은 모서리, 단색 파스텔 | 여러 날에 걸친 하나의 업무를 연결된 기간으로 표현한다. |
| 막대 제목 | 약 11px, 작은 색 사각형과 한 줄 이름 | 긴 제목은 말줄임하고 전체 이름과 기간을 상세에서 확인한다. |
| 주 경계 | 다음 주에 이어지는 막대 | 잘린 모서리와 연결 표현을 유지하고 같은 업무로 이동한다. |

기존 참조 HTML의 수치도 대조했다. 월 제목은 29px/600, 프로젝트 칩은 약 20px, 요일은 10px/700, 날짜는 11px/600, 일정 막대는 약 17px, 막대 간 간격은 약 21px였다. 이 수치를 절대 좌표로 복사하지 않고 화면의 밀도와 계층을 맞추는 근거로 사용한다.

## 색과 의미

| 구분 | 배경 | 글자 | 작은 색 기호 |
| --- | --- | --- | --- |
| 프로젝트 1 | `#E9F4E6` | `#1F8E00` | `#B1D8A6` |
| 프로젝트 2 | `#F4E6ED` | `#8C0043` | `#D4A0B9` |
| 프로젝트 3 | `#EDECFF` | `#4B42FC` | `#BCB9FE` |
| 프로젝트 4 | `#E8E8E8` | `#444444` | `#ABABAB` |

프로젝트 색과 일정 상태의 의미를 섞지 않는다. 프로젝트 칩과 기간 막대에는 같은 프로젝트 색을 쓰고, 크리티컬·조건부 관계·마일스톤은 기호와 범례를 함께 표시한다. 선택과 편집에는 SUNJIN의 주황색 `#F47920`을 절제해 사용한다.

다른 달 날짜는 옅은 회색, 오늘 영역은 `#F7F7F7`, 일반 경계는 `#EDEDED` 계열로 처리한다. 색만으로 필요한 정보를 전달하지 않는다. 글꼴은 기존에 자체 호스팅하는 Pretendard를 유지한다.

## 이전 마스터 화면과의 차이

- 큰 요약 카드와 반복된 도구줄이 차지하던 시각적 비중을 줄여 일정 본문을 우선한다.
- 회녹색 위주의 본문을 검정·중립 회색으로 정리하고, 파스텔 색은 프로젝트 구분에 사용한다.
- 일별로 같은 업무를 반복하던 캘린더는 주별 기간 막대로 바꾸어 실제 시작과 완료를 읽기 쉽게 한다.
- 간트의 고정 열·행 좌표·관계 연결점은 유지하면서 막대와 시간축의 시각적 밀도를 맞춘다.
- 간트·업무 목록·캘린더는 같은 프로젝트 마스터 일정의 서로 다른 보기라는 계층을 유지한다.

## 데이터와 표현을 분리하는 원칙

1. 이미지의 프로젝트명, 날짜, 미팅, 리서치 항목을 실제 일정 데이터로 가져오지 않는다.
2. 프로젝트 칩은 현재 작업공간과 실제 연결된 프로젝트만 표시한다. 프로젝트 수를 채우기 위한 예시를 기본 데이터에 넣지 않는다.
3. 원본에 없는 담당자·진척·승인 상태를 디자인 요소로 만들어 넣지 않는다.
4. 시작일·완료일·실제일·상태일·원본 출처를 보존한다. 디자인 변경으로 계산 모드를 바꾸지 않는다.
5. 업무·마일스톤·승인게이트 등 실제 지원하는 유형을 범례에 사용한다.
6. 표시 개수 제한은 화면만 정리한다. 숨겨진 개수와 날짜별 전체 목록을 제공하고 계산 모델은 유지한다.
7. 프로젝트 필터, 검색, 단계 필터와 현재 선택을 이용해 표시 범위를 바꾼다. 필터가 입력 데이터를 삭제하거나 계산 관계를 바꾸지 않는다.
8. 실제 일정이 담긴 검증 스크린샷과 원본 문서를 공개 빌드에 포함하지 않는다.

## 반응형과 상호작용 검수 기준

- 데스크톱과 중간 폭에서 제목·프로젝트 칩·범례가 서로 겹치지 않는다.
- 모바일에서 페이지 전체의 가로 넘침을 만들지 않는다. 필요한 탭의 가로 이동은 해당 탭 영역 안에서 처리한다.
- 작은 화면에서 글자를 과도하게 줄이지 않고 칩·범례·보조 도구를 자연스럽게 줄바꿈한다.
- 기간 막대는 주 경계를 넘어도 같은 업무를 가리킨다. 월말·윤년·같은 날 마일스톤·겹치는 기간을 확인한다.
- 일정 선택, 날짜별 더 보기, 월·주 전환, 날짜 이동, 상세 패널 진입이 작동한다.
- 프로젝트 색과 이름이 일치하며, 외부 프로젝트의 업무 선택은 해당 프로젝트의 상세를 연다.
- 간트의 막대 이동·기간 변경·관계 편집·실행취소와 원본 일정 재현이 유지된다.
- 최종 빌드를 실제 Chromium에서 여러 화면 폭으로 확인하고, 관찰 결과와 캡처는 검증 자료로 분리 보관한다.
