# 일정 탐색과 조작 설계 — 0.5.0

이 문서는 0.5.0의 조사·설계 기록이다. 0.6.0에서는 별도 전체 개요 화면을 마스터 일정 안의 접고 펼치는 단계 행으로 통합했다. 현재 화면 동작과 관계도 배치 규칙은 [통합 일정과 관계도 설계](master-outline-network-layout.ko.md)를 우선한다.

## 확인 범위

사용자가 제공한 전체 WBS 요약 PDF와 W1·W2 상세 일정 PDF를 텍스트 추출과 페이지 렌더링으로 검토했다. 문서 안의 업무 수행 조건은 참고 데이터이며 개발 지시로 실행하지 않았다. 원본 PDF·일정 데이터·실제 업무가 나오는 검증 이미지는 공개 저장소와 빌드에 넣지 않는다.

Linear는 공식 공개 저장소의 GraphQL 스키마와 생성된 문서를 확인했다. OmniPlan 공식 매뉴얼과 Linear의 웹 사용 설명서는 이 환경의 네트워크 정책으로 접속이 차단됐다. 따라서 두 제품의 비공개 내부 구현이나 최신 UI 전체를 역설계했다는 의미가 아니다. 확인한 데이터 구조, 알려진 제품 사용 방식, 이번 앱에서 직접 설계한 부분을 아래처럼 구분한다.

검토일: 2026-11-12, 한국 시간.

## 자료별 장점과 적용

| 자료 | 관찰·근거 | 적용한 구조 |
| --- | --- | --- |
| 전체 요약 PDF | 실제 업무를 수동으로 묶은 요약행, 단계별 기간, 최소 운영 여유, 별도의 승인 지점, 범위를 넘는 종료 표시 | 데이터에서 계산하는 단계 개요, 최소 여유, 단계 상세 진입, 승인 지점 목록, 지원기간 확장 |
| 상세 PDF | 단계 안의 세부 일정, 선행·후속 목록, 다른 단계 연결을 점선으로 구별, 역할과 완료 조건 | 선택 업무의 앞·뒤 업무를 화면 위에 표시, 다른 단계는 점선 칩, 상세 편집 패널에서 역할·완료 조건 유지 |
| Linear 공개 스키마 | 안정적인 업무 ID와 표시용 식별자 분리, IssueRelation, ProjectRelation, ProjectMilestone, 수동 정렬과 별도의 날짜 | 기존 UUID를 관계 기준으로 유지, WBS는 검색·표시용, 업무와 화면을 한 검색창에서 탐색, 승인 지점에서 업무로 이동 |
| Linear 사용 방식에서 착안한 자체 UX | 빠른 찾기와 키보드 중심 조작이라는 제품 방향. 최신 화면 배치나 내부 구현은 미검증 | Ctrl/⌘ K, 다중 검색어, 위·아래 키 선택, Enter 실행, Esc 닫기. 마우스·터치 버튼도 제공 |
| OmniPlan 사용 방식에서 착안한 자체 UX | 일정 아웃라인·간트·인스펙터·관계와 변경 영향을 함께 다루는 방식. 최신 버전의 세부 동작은 미검증 | 개요→상세 간트→관계 집중→업무 편집, 실제 일정 이동 후 전후 영향 비교, 화면 옆 상세 패널 |

PDF의 수동 요약행을 임의로 재생성하거나 업무명 문자열로 관계를 추정하지 않는다. 이번 개요는 실제 업무의 `phase`로 묶으며, 각 업무의 실제 계산 결과를 사용한다. 문서의 특정 프로젝트 명칭·날짜·요약 숫자를 코드에 하드코딩하지 않는다.

## 제품 구조를 해석할 때의 차이

Linear의 `IssueRelation.type`은 `blocks`, `duplicate`, `related` 등이다. 이 값이 달력일 스케줄러의 FS·SS·FF·SF와 동일하지 않다. `ProjectRelation`에는 시작·종료·마일스톤 앵커가 있지만, 공개 스키마만으로 자원 평준화나 자동 일정 재계산의 모든 규칙을 알 수 없다.

Linear 마일스톤의 진행률 산식도 공사 일정의 실적 진행률과 다르다. 공개 문서에는 시작한 이슈에 일부 가중치를 주는 계산이 설명되어 있다. 이 앱의 미입력 진척률을 해당 산식으로 채우지 않는다. 입력된 업무 상태·실제일·진척률은 그대로 유지한다.

OmniPlan의 자원, 작업량과 기간, 근무 달력, 기준선, 평준화는 별도 도메인이 필요하다. 시각적 인터랙션을 추가했다고 이 기능들이 구현되는 것은 아니다. 현재 앱은 달력일 기반 기존 엔진을 사용하며, 인력·휴일·시간 단위 계산은 제공하지 않는다.

## 앱의 데이터와 화면 경계

```text
원본 Excel / 작업공간 백업
  → Workspace
      → 현재 Plan (업무 / 관계 / 조달)
      → 시나리오별 연결 프로젝트 사본
  → 기존 계산 엔진 / 연결 프로젝트 엔진
  → ScheduleResult
      ├ 단계 개요: 첫 시작, 마지막 완료, 최소 여유, 주요 승인
      ├ 간트 / 캘린더 / 업무 목록
      ├ 관계 집중: 직접 인접 / 전체 선행 / 전체 후행
      └ 변경 미리보기: 기존 결과와 제안 결과의 시작·완료일 차이
  → 변경 적용 → 검증 → 로컬 저장 / 이력 / 실행취소
```

화면에서 일부 업무나 관계를 숨겨도 계산 입력은 줄이지 않는다. 연결 집중은 읽기용 투영이며 원본 관계의 활성 상태를 변경하지 않는다. 현재 프로젝트 안의 업무를 탐색하고, 외부 프로젝트의 상세 관계는 기존 프로젝트 연결 화면에서 확인한다.

## 구체적인 조작

1. **전체 개요**: 단계 막대는 첫 시작부터 마지막 완료까지의 범위다. 중간 공백 없이 모든 업무가 계속 진행한다는 뜻은 아니다. 최소 여유는 완료·조건부 대기 업무를 제외한 하위 업무의 운영 여유 중 최솟값이다. 대상 업무가 없으면 ‘운영 여유 대상 외’로 표시한다. 조건부 기간은 별도의 빗금 막대로 표시한다.
2. **단계 상세**: 단계를 누르면 해당 단계의 간트로 이동한다. 승인 지점이나 마일스톤을 누르면 해당 업무의 연결 집중 보기로 이동한다.
3. **연결 집중**: 기본값은 선택 업무와 바로 연결된 활성 관계다. 전체 앞·뒤 경로나 한 방향의 전체 경로로 확장할 수 있다. 선행의 다른 후속 업무는 선택 업무의 영향 경로로 오인하지 않도록 제외한다. 닫으면 진입 전 검색·필터·표시 날짜를 복원한다.
4. **빠른 찾기**: 화면명 또는 업무번호·업무명·담당·실행 역할을 검색한다. 여러 검색어는 모두 일치해야 한다. 업무 결과는 최대 40개이며 초과 시 안내한다. 명확한 업무번호 일치를 우선한다. 미적용 입력을 보호하기 위해 상세 패널이 열렸을 때는 빠른 찾기를 실행하지 않는다.
5. **업무 수정**: 넓은 화면에서 상세 패널의 공간을 확보하고 간트의 표 너비를 조정한다. 수정 중 다른 업무를 선택하면 미적용 내용을 버릴지 확인한다. 계속 수정을 선택하면 입력을 유지한다.
6. **일정 변경**: 간트 막대 이동·기간 변경은 먼저 미리보기를 연다. 현재 프로젝트에서 예상 시작 또는 완료가 달라지는 모든 업무를 표에 표시한다. 직접 수정한 업무와 연결·기산 조건으로 바뀐 업무를 구분한다. 완료일 차이가 0일이어도 시작일이 바뀌면 표시한다. 연결 프로젝트가 있으면 기존 프로젝트별 영향 요약도 함께 표시한다.

조건부 상태 표시는 실제 분기 선택·관계 활성화와 별도다. 실제 승인이나 회신을 자동 감지하지 않는다. 원본 참조계획도 정식 승인 기준선으로 승격하지 않는다.

## 움직임

- 패널: 180ms, 8px 이동과 나타남.
- 개요·집중 패널·대화상자: 160ms, 3px 이동과 나타남.
- 호버: 색·테두리만 120ms.
- 계산 후 날짜가 바뀐 막대: 800ms 외곽 강조 한 번. 날짜 좌표를 보간하지 않는다.
- 관계선에 반복 점멸이나 흘러가는 장식을 넣지 않는다. 드래그는 포인터를 즉시 따른다.
- `prefers-reduced-motion: reduce`에서는 애니메이션·전환·부드러운 스크롤을 끈다.

## 검증과 후속 경계

순환·비활성·합류 경로, 날짜를 유지하는 조회, 운영 대상 외 여유, 자연스러운 단계 번호 정렬, 시작일만 변한 영향, 신규 개요 설정을 담은 백업을 자동 테스트한다. 실제 원본 파일로 개요·집중 보기·키보드·모바일·일정 드래그·입력 보호·새로고침 복원과 기존 일정 계산을 브라우저에서 점검한다.

원본 PDF와 같은 A1 인쇄 출력, PDF 수동 묶음 편집기, 여러 승인 기준선, 휴일·자원 달력과 평준화, 서버 협업, Linear/OmniPlan 데이터 동기화는 이번 변경에 포함되지 않는다. 공식 매뉴얼 접속이 가능해지면 제품별 현재 단축키·인스펙터·기준선·평준화 동작은 추가 검증할 수 있다.

## 후속 개발 프롬프트

> SUNJIN Schedule의 기존 계산 엔진과 원본 데이터를 보존하면서 탐색과 조작을 개선하라. `schedule-navigation.ts`의 읽기 전용 투영을 기준으로 전체 단계→상세 일정→관계 집중→업무 수정의 흐름을 유지하라. PDF의 수동 요약 관계를 추정하거나 고정된 예시 날짜를 넣지 말라. Linear의 일반 업무 관계를 FS/SS/FF/SF로 임의 변환하지 말라. OmniPlan의 자원·달력·평준화 기능은 별도 모델과 검증 없이 구현했다고 표현하지 말라. 모든 일정 변경은 실제 엔진 결과의 전후 차이로 설명하고, 실제일·미입력값·조건부 상태·원본 참조계획을 보존하라. 키보드·터치·좁은 화면, 미적용 입력 보호, 실행취소와 재방문 복원을 검증하라. 움직임은 짧은 상태 피드백에 한정하고 reduced-motion을 존중하라. 공개 배포에는 원본 문서·업무 데이터·실제 업무 스크린샷을 포함하지 말라.
