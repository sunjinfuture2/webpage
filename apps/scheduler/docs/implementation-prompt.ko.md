# 연결 일정 후속 검증·확장 프롬프트

이 프롬프트는 2026-11-09의 연결 일정 개발 뒤 후속 작업에 사용한다. 먼저 실제 코드와 검증 결과를 읽어 현재 구현된 기능과 남은 항목을 구분한다. 같은 변경을 처음부터 다시 적용하지 않는다.

```text
SUNJIN Schedule의 연결 간트와 프로젝트 간 영향 분석을 검증·확장하라.

[출발점]
최신 작업본, 저장소 지침, docs/connected-schedule.md, README와 테스트를 읽어라.
이전 대화의 커밋을 최신 구현이라고 가정하지 말고 기존 사용자 변경을 보존하라.
현재 제공되는 기능을 확인한 뒤 결함·누락을 중심으로 작업하라.

현재 구현 계약은 다음과 같다.
- 한 프로젝트의 FS/SS/FF/SF 관계와 정수 달력일 간격
- 간트 연결선 선택, 관계 생성·수정·삭제, 선행·후행 탐색
- 선택 업무를 중심으로 한 업무 관계도와 표시 범위 안내
- 가져온 로컬 프로젝트 사이의 관계와 전체 그래프 계산
- 프로젝트별 시나리오·상태일·실제일·조달·지원기간 유지
- 입력 변경 전후 날짜·영향 업무·영향 프로젝트 비교
- 기존 백업을 보존하는 선택적 portfolio 데이터와 전체 작업공간 이력

[공식 자료]
docs/connected-schedule.md의 MicrosoftDocs/VBA-Docs 출처를 다시 확인하라.
TaskDependency, PjTaskLinkType, Lag/LagType, LinkTasksEdit,
ExternalTask, StartDriver, TotalSlack, Calendar, Manual,
ConstraintType과 자원 달력·평준화를 구분하라.

원문에서 확인한 동작과 제품별 최신 지원 범위를 분리하라.
데스크톱 Project의 개체 모델을 현재 Planner 라이선스 기능표로 설명하지 마라.
접근하지 못한 문서나 실제로 대조하지 않은 파일을 검증 완료로 표시하지 마라.

[디자인]
사용자의 WorkSpace 디자인을 계승하라.
Pretendard, #F47920, 검정 제목, 중립색 본문, 밝은 사이드바,
얇은 구분선과 우측 상세 패널을 유지하라.
새 참조 URL에 접근할 수 있으면 실제 화면과 비교하라.
1920px 고정 폭과 전역 스크립트를 앱에 이식하지 마라.

간트·관계도·프로젝트 화면의 글꼴·간격·상태색·버튼 규칙을 맞춰라.
실제 담당자·진척·작업량이 없는 원본에는 임의 값을 넣지 마라.

[일정 정확도]
원본의 달력일·양끝 포함 기간과 마일스톤 규칙을 유지하라.
근무시간 기반 모드는 별도 명시적 프로필로 구현하고 원본을 자동 전환하지 마라.
현재 계산 모드를 Microsoft Project의 근무시간 계산과 동일하다고 부르지 마라.

프로젝트 간 선후행 계산은 모든 활성 내부·외부 관계를 검증해야 한다.
같은 로컬 업무 ID가 여러 프로젝트에 있어도 충돌하지 않게 하라.
상태일, 실제일, 잔여기간, 조달 조건, 월 기준 지원기간을 보존하라.
전역 그래프의 순환과 누락 참조를 원인 경로와 함께 안내하라.

연결된 업무, 날짜가 실제로 바뀐 업무, 날짜를 결정한 조건을 구분하라.
여유가 지연을 흡수하는 경우도 결과에 반영하라.
프로젝트별 완료·운영 목표와 전체 목표의 여유를 구분하라.
기간이 있는 목표 업무의 늦은 시작·완료 계산도 검증하라.

[저장과 화면]
기존 v1 JSON/XLSX 작업공간 백업을 계속 읽어라.
선택적인 portfolio 데이터의 중첩·중복·잘못된 참조를 검증하라.
가져온 프로젝트와 원본 외부 시스템의 실시간 공유를 혼동하지 마라.
여러 프로젝트를 바꾸는 입력·관계·이력을 일관된 변경으로 저장·복원하라.
다른 탭의 저장 충돌 보호와 이전 데이터 복구 경로를 유지하라.

화면별 결과 버전을 맞추고 오래된 계산으로 최신 화면을 덮어쓰지 마라.
정렬·필터·단계 접기·가상화 후에도 관계 참조를 유지하라.
숨겨진 관계·노드 수와 이동 수단을 표시하라.
키보드·모바일에서 상세 폼으로 관계를 편집할 수 있게 하라.

[검증]
공개 검증에는 합성 프로젝트만 사용하라.
네 관계 유형, 음수 간격, A→B 전파, 여유 흡수, 무관한 C 유지,
프로젝트를 넘는 순환 거부, 실제일 유지, 상태일 차이,
조달·지원기간 참조, 저장·재시작·백업·이력 복원을 검증하라.
원본 회귀 검사는 비공개 자료를 사용하고 공개 빌드에서 제외하라.

실제 브라우저에서 관계 생성·편집·삭제,
관계도 탐색·확대·축소·노드 제한,
프로젝트 연결·변경 영향·저장·복원과 모바일을 확인하라.
큰 합성 그래프의 계산과 렌더링 성능을 측정하고 목표와 측정값을 구분하라.

[후속 기능]
근무시간 달력, 자원 배정·평준화, 여덟 제약,
정식 승인 기준선, 서버 인증·권한·공동 편집,
MPP/Project XML, 홈페이지 캘린더·자료실 통합은
사용자가 지정한 범위를 확인해 별도 구현하라.

작업 후 실제 구현·부분 구현·후속 항목,
공식 출처 확인일, 테스트 결과, 미확인 호환 동작을 기록하라.
공개 결과에 원본 업무 문서와 실제 일정 스크린샷을 포함하지 마라.
게시 범위는 사용자 지시에 따른다.
```
