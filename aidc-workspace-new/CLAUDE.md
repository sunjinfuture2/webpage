## How the app is put together (since the 2026-11 rework)

- original.html is the app itself (markup, styles, data fixtures, all screen logic). It started as a copy of aidc-workspace.html from sunjinfuture2/simulator but has diverged for good: never overwrite it with the simulator design; port design changes by hand. build-shared.mjs only (1) regenerates seed.json from the fixtures, (2) injects shared-client.js at the LOGIN marker and (3) syntax-checks the result.
- Login is by 사번 only, no password (owner decision, 2026-11-12). The same 사번 may be signed in on several tabs / devices. The token lives in localStorage (`aidc-token`), so all tabs of one browser share the login; logging out signs out every tab.
- Version gate (currently 4): every /api call except GET /api/file/* must send `X-AIDC-Client` (or `?v=` on the websocket) >= MIN_CLIENT in shared-worker.mjs. When the wire format changes, raise MIN_CLIENT and CLIENT_VERSION (shared-client.js) together; pages of an older build are then refused and told to reload.
- Sync: the client diffs its state against the last server copy every 250 ms and posts field-level changes for items, projects and the metas listed in FIELD_META (others are whole records). Server answers and broadcasts are merged field by field (mergeRecord): a field this person has not touched always follows the server, so concurrent edits of different fields and comments added while someone else edits are kept. A 409 / 423 never blocks later saves; the client refetches and merges (sharedResolveConflict). Two rules keep an older copy from undoing a newer change (2026-11-23, the theme flipping back and forth): a whole state that was asked for before a save or a socket message and arrives after it is dropped and asked for again (sharedSeq), and a page skips its own save coming back over the socket (the save's `src`, handed on by the Worker).
- Editing an item or a project overview takes a server lock. While editing, the record is held back from sync until 저장; 취소 restores the snapshot. Comments are not locked.
- Leaving an edit: since 2026-11-23 the owner wants to be asked while the preview is on ("저장 안 하고 닫을 거냐고 팝업"): guardLeaveAsk shows a window with 계속 작성 / 저장 안 함 / 저장 (tests/schedule-13.cjs). Without the preview the rule of 2026-11-18 still holds: nothing is asked, guardLeave saves what was being edited on the way out (an existing item as with 저장, with a 되돌리기 action in the toast; a new item as a draft, titled "제목 없음" when it has no title; a project overview and a partner / link card as with their 저장 button) and releases an edit in which nothing changed. It only holds the move back while a file is still uploading or a required name is empty. Ctrl+S saves. Do not bring a dialog to the page without the preview. tests/leave-1.cjs covers this.
- Drafts (status `draft`) are saved on the server but only their author sees them (canSee / isLive; the Worker's privateDraft sends them to nobody else, whatever flags they carry). Items with status `new` exist only in the open panel. Unsaved typing is kept in localStorage (`aidc-recovery:<사번>`, v2) and restored once as a "[복구 초안]" draft.
- Dates are real: TODAY is the browser date. Lists are driven by type / status / project, not by the old `table` / `card` / `cal` fixture flags (those only keep demo drafts visible). New items sort first. 자료실 rows live in ARCH_ROWS until first edited, commented or trashed; then adoptRow turns them into normal items with `arch: <tab>`.
- Shared settings records: meta:notices, meta:settings (workspace name, dropbox link, teamspaces, security), meta:members (role, email, teamspaces per 사번), meta:inbox:<사번> (read state, put-away notices, my own settings `prefs`; sent to nobody else). Notifications are derived from comments / mentions, not stored. Roles: until someone is 소유자 everybody may manage; from then on the Worker itself refuses what the page hides (roles() / denied() in shared-worker.mjs, see MYPAGE.md).
- Trash: items get `status:'trash'` + `trashedAt`; the Worker purges them (and their files) after 30 days, at most hourly. Partners and 자료실 cards use `trash` + `trashedAt` flags, deleted projects wait in SETTINGS.projTrash; the Worker purges all of them too. Restoring an item goes back to `prevStatus`, or to a draft when that is not recorded (never straight to published). Deleting for good is for an owner.
- Attachments: files are uploaded as base64 to POST /api/file and stored in the Durable Object's files table (1.8 MB cap per file, SQLite row limit). The page embeds only /api/file/<id> links (download) or ?inline=1 (images, PDF, media; HTML is never served inline). Downloads and inline images are plain browser requests, so /api/login and /api/state also set an HttpOnly aidc_file cookie scoped to /api/file that GET /api/file/* accepts in place of the Bearer token. Only the uploader may delete a file. Bodies are cleaned of scripts, inline handlers and javascript: links on the server (cleanHtml) and again when shown (cleanBody).
- Activity: /api/history feeds 설정 > 업데이트 and 감사 로그 (one compact line per change, no bodies).
- Wording of content written into the workspace (descriptions of links, cards, partners and the like): short notes that end in a noun, e.g. "GPUaaS와 자체 AI 인프라를 운영하는 국내 업체." — not polite sentences ("…업체입니다."). Owner's rule, 2026-11-16.
- 자료실 link cards show the site's logo in the box above the title (logoImg: Google favicon service by host name, then <origin>/favicon.ico, then the plain grey box). Partners and link cards are edited in place like the project overview (S.editSimple, data-sk fields, 저장 / 취소); there is no separate edit form.
- 자료실 click rule (owner, 2026-11-16): the title of a link card or of a table row is a link that opens the site in a new tab (underlined on hover); clicking anywhere else opens the content panel. Rows without a real address keep a plain title. Link cards are grouped by purpose (topic sections), not by medium, and one site is registered once; cards may carry a `note` (활용 시 주의).
- One-time data additions run from sharedStart behind a meta:flags entry and use fixed ids (see addReferenceLinksV1 / restyleReferenceLinksV2), because the production site cannot be reached from the build environment.
- Layout: the design is 1920 wide. fitLayout() gives extra width to the content (--d), tightens --d down to -200 on narrower windows and then scales #app with CSS zoom. Mouse math inside #app must divide by LAYOUT.zoom.
- Body editor (2026-11-18): item bodies are written with the block editor in editor/ (Tiptap 3 / ProseMirror, MIT only), bundled by the build into public/editor.js and used through window.AIDCEditor. Read EDITOR.md before touching it: it describes the stored HTML (schema v2, items carry `ed: 2`), how first-editor bodies are converted (only when somebody edits and saves; the original is kept once in `bodyV1`), the off switch, and which items of the owner's brief are done / partial / not done. Rules that are easy to break: (1) never write to the editor's DOM, every change is a command / transaction; (2) a body is stored only as what the schema serialises, so a new block needs a node in editor/schema.js with both parseHTML and renderHTML, read-mode CSS and, if it depends on live data, a line in hydrate(); (3) the app keeps one editor per edited item in NB[id] and re-attaches it after every redraw of the pin (nbMount, called from fitTitle) — do not create editors anywhere else; (4) sharedUi must not set contenteditable on `.ibody[data-nb]`; (5) the item r5cdb8f30-… and research-editor-trial.js belong to another experiment and keep the first editor; (6) run tests/editor-1..7.cjs and tests/leave-1.cjs (315 checks, one after another on a fresh local database) after any change in editor/; (7) every "own undo step" goes through closeHistory from editor/hist.js, never from @tiptap/pm/history directly (the shared document has another undo stack); (8) KaTeX is not in the bundle: the build copies it to public/katex and math.js loads it on demand.
- Body editor, second and third round (2026-11-18): code languages and colours, equations, find and replace, export / import, templates, button block, block comments (item comments with `block` / `quote` / `resolved`), synced block and item list (only the reference / the conditions are stored), date reminders (derived in notifications(), no server scheduler), a "⋯" document menu in the item header (nbDocMenu / nbDocExtra), suggesting changes (editor/suggest.js: text-level only; inserted text is marked in appendTransaction, never through stored marks, because ProseMirror ends an IME composition when stored marks appear). A to-do ticked or a button pressed in read mode is a small save of its own (nbQuickEdit).
- Version history: the Worker keeps a version of a published item's title and body per saving request in table `versions` (see version() in shared-worker.mjs; `old` is mutated in place by the change loop, so the pre-request snapshot is taken first). GET /api/versions?item= and /api/version?id=; drafts have none.
- Editing together: "함께 수정" joins another member's edit (POST /api/lock action `join` -> table `co_locks`; locks() lists them under `co`; the first joiner is promoted when the holder leaves). The body then is a Yjs document relayed over the /api/live socket (messages with `y`: join / state / up / aw / hello / left / leave / no; the Worker merges updates into `ydocs` and drops the row when the last editor leaves). The first editor's page turns its document into the shared one only when somebody joins (nbCoWatch -> nbUpgrade), so editing alone never runs this code. The saved `body` stays the only lasting copy; a member who joined (`it._co`) takes the body others save as the base of their own save (sharedApply). lockMine() / otherLock() treat a lock I edit along with as mine. An edit made with the first editor answers `no`.
- Panel <-> full page (owner, 2026-11-18): "전체 페이지로 열기" grows the panel to the size of the page and only then swaps to the full page; the way back is a pictogram only (#full-shrink, title "패널로 좁히기") at the top left of the full page; it swaps to a full-size panel that shrinks (expandPanel / shrinkFull / panelGrow: --panelw and the side margins of #panel-pin are animated together, pinSettle slides the parts whose vertical place differs between the two layouts). The panel's icons (#panel-ic: close, expand, shrink) are a child of #main, not of the top bar, because they travel with the panel's edge and come down below the top bar while it grows (--panel-k / --panel-ky); at full size the expand icon arrives exactly where the shrink pictogram sits (72 px from the left of #main, 61 px down), clear of the grey "사이드바 펼치기" square that shows when the sidebar is folded. Both buttons keep the caret where it is. The width handles stop at their limits (panel 900–1500, sidebar 220–440) and swallow the click that follows the drag, which used to count as a click outside the panel and closed it. Do not make the handle close anything. tests/panel-1.cjs covers this.
- Client-side preferences (favorites, recent items, sidebar / panel width) live in localStorage per browser; search text, filters, sort and scroll position live in sessionStorage and survive a reload. The address (#page=…&proj=…&full=…&panel=…) always describes the open screen, so back / forward and shared links work.
