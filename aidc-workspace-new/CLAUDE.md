## How the app is put together (since the 2026-11 rework)

- original.html is the app itself (markup, styles, data fixtures, all screen logic). It started as a copy of aidc-workspace.html from sunjinfuture2/simulator but has diverged for good: never overwrite it with the simulator design; port design changes by hand. build-shared.mjs only (1) regenerates seed.json from the fixtures, (2) injects shared-client.js at the LOGIN marker and (3) syntax-checks the result.
- Login is by 사번 only, no password (owner decision, 2026-11-12). The same 사번 may be signed in on several tabs / devices. The token lives in localStorage (`aidc-token`), so all tabs of one browser share the login; logging out signs out every tab.
- Version gate: every /api call except GET /api/file/* must send `X-AIDC-Client` (or `?v=` on the websocket) >= MIN_CLIENT in shared-worker.mjs. When the wire format changes, raise MIN_CLIENT and CLIENT_VERSION (shared-client.js) together; pages of an older build are then refused and told to reload.
- Sync: the client diffs its state against the last server copy every 250 ms and posts field-level changes for items, projects and the metas listed in FIELD_META (others are whole records). Server answers and broadcasts are merged field by field (mergeRecord): a field this person has not touched always follows the server, so concurrent edits of different fields and comments added while someone else edits are kept. A 409 / 423 never blocks later saves; the client refetches and merges (sharedResolveConflict).
- Editing an item or a project overview takes a server lock. While editing, the record is held back from sync until 저장; 취소 restores the snapshot. Comments are not locked.
- Drafts (status `draft`) are saved on the server but only their author sees them (canSee / isLive). Items with status `new` exist only in the open panel. Unsaved typing is kept in localStorage (`aidc-recovery:<사번>`, v2) and restored once as a "[복구 초안]" draft.
- Dates are real: TODAY is the browser date. Lists are driven by type / status / project, not by the old `table` / `card` / `cal` fixture flags (those only keep demo drafts visible). New items sort first. 자료실 rows live in ARCH_ROWS until first edited, commented or trashed; then adoptRow turns them into normal items with `arch: <tab>`.
- Shared settings records: meta:notices, meta:settings (workspace name, dropbox link, teamspaces, security), meta:members (role, email, teamspaces per 사번), meta:inbox:<사번> (read state). Notifications are derived from comments / mentions, not stored. Roles are enforced in the UI only (there is no password): until someone is 소유자 everybody may manage.
- Trash: items get `status:'trash'` + `trashedAt`; the Worker purges them (and their files) after 30 days, at most hourly. Partners and 자료실 cards use `trash` + `trashedAt` flags and are purged by the client at start-up.
- Attachments: files are uploaded as base64 to POST /api/file and stored in the Durable Object's files table (1.8 MB cap per file, SQLite row limit). The page embeds only /api/file/<id> links (download) or ?inline=1 (images, PDF, media; HTML is never served inline). Downloads and inline images are plain browser requests, so /api/login and /api/state also set an HttpOnly aidc_file cookie scoped to /api/file that GET /api/file/* accepts in place of the Bearer token. Only the uploader may delete a file. Bodies are cleaned of scripts, inline handlers and javascript: links on the server (cleanHtml) and again when shown (cleanBody).
- Activity: /api/history feeds 설정 > 업데이트 and 감사 로그 (one compact line per change, no bodies).
- Layout: the design is 1920 wide. fitLayout() gives extra width to the content (--d), tightens --d down to -200 on narrower windows and then scales #app with CSS zoom. Mouse math inside #app must divide by LAYOUT.zoom.
- Client-side preferences (favorites, recent items, sidebar / panel width) live in localStorage per browser; search text, filters, sort and scroll position live in sessionStorage and survive a reload. The address (#page=…&proj=…&full=…&panel=…) always describes the open screen, so back / forward and shared links work.
