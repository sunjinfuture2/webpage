# 액션 업로드2 (시험판)

기존 업로드는 그대로 유지한다. 프로젝트 액션의 업로드 오른쪽에 업로드2를 추가했다.

- .xlsx 한 파일에서 시트·머리글 행을 선택하고 업무 번호, 업무명, 시작일, 완료일, 담당자, 상태, 진척률, 단계를 연결한다. 같은 머리글의 연결 설정은 해당 브라우저 localStorage에 저장한다.
- 적용 전에는 서버 업무를 변경하지 않는다. 기존 업무와 엑셀 값을 나란히 확인하고 필드별로 선택한다. 누락 업무와 빈칸은 기본 유지한다. 날짜/업무명 빈칸으로 필수값을 삭제하지 않는다. 선택한 누락 업무 삭제는 기존 엔진의 연결 보호 규칙을 따른다.
- 기존 WBS 또는 과거 업로드2에서 확인한 외부 업무 번호(up2keys)로 연결한다. 이름만 같으면 확인을 요구한다. 사용자가 기존 업무를 직접 선택할 수 있다. 기존 내부 ID와 WBS를 유지하여 본문·댓글·첨부 연결을 보존한다. 새로운 외부 번호는 임의 문자열이어도 가능하며 내부 WBS를 생성한다.
- 담당자는 등록된 멤버 이름/사번만 연결한다. 이름이 중복되면 사번으로 입력한다. 오류 행은 이유를 표시하고 적용을 차단한다. 사용자가 명시적으로 그 행을 제외할 수 있다.
- 검토 중 프로젝트 일정이 변경되면 적용을 중단하고 재검토를 요구한다. 적용은 일정 override를 사용한다. up2last에 마지막 적용 파일/시트/시각/사용자/건수를 기록하며 되돌리기에 업무와 외부 번호 연결을 함께 포함한다.
- 이 시험판은 액션 목록 전용이다. 선후행 관계·조달·승인게이트·근거 시트는 기존 업로드를 사용한다. 선택한 시트만 읽으며 신규 업무는 제목·시작일·완료일이 필요하다. 25MB, 5,000행, 128열을 넘으면 조용히 자르지 않고 안내한다. 모호한 연도 없는 날짜는 거부한다.
- 별도 로컬 DB에서 tests/upload2-check.cjs로 실제 xlsx 업로드·선택·취소·적용·새로고침·업무 연결·되돌리기·오류·동시 변경을 검증한다. 전체 회귀검사는 실행하지 않는다.
